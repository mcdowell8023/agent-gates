## 1. 问题陈述

agent-gates §8 路由只判断 L0-L3 能力等级 + waterfall fallback（opencode→codex→...）。但**没解决三件事**:

1. **选型靠运气**：审查具体用哪个模型，靠 agent 临场或用户记忆。本会话实测发现：opencode 一直只用 gpt-5.5，白瞎了它多 provider 的优势；flash 模型审查直接空/损坏输出却没人拦。
2. **伪异构**：本会话长期并行两个 GPT（opencode-gpt + codex），都是 GPT，靠脚手架差异凑"异构"，违背红线 #8"不同 vendor"本意。
3. **不可配置**：`review-capability.json` 由 doctor 无条件覆盖，用户手改会被冲掉。

## 2. 12 家横评 evidence（选型规则的实证依据）

本会话对同一方案跑了 12 个模型，结论:

| 类别 | 模型 | 结果 |
|------|------|------|
| 有效（pro/max 级，独有洞察） | gpt-5.5 / codex / gemini-3.1-pro / deepseek-v4-pro / deepseek-v4-flash(opencode) / qwen3.7-max / qwen3.7-plus / xfyun-qwen3.6 / kimi-k2.6 | 各抓到不同盲点 |
| **不可靠（剔除）** | qwen3.6-flash（输出损坏）/ deepseek-v4-flash(bailian)（空）/ glm-5.1（空） | flash/小模型不能审查 |

**三条实证规律 → 选型规则:**
- **flash/小模型剔除**：空输出或损坏，审查要推理
- **claude 系排除**：跟发起方（Claude Code）同源，不算异构
- **同 vendor 多档位去重**：qwen 3 档 / deepseek 2 档盲点重合，多跑零收益
- **跨 vendor 才有新盲点**，但 3-4 vendor 后枯竭 → panel 封顶 2 副审

## 3. 设计

### D0. 绕开 OMO 编排（最高优先，调用正确性前提）

**根因（v0.3 实测）**：`opencode run` 默认走 OMO(oh-my-opencode) 注入的编排 agent(Sisyphus/Hephaestus 等)，审查任务被识别成"需探索的复杂任务"→ 模型被注入"意图检测 + 派子任务"行为 → 编排失败("explore 还在跑"就退)或宽松假阳性。

**v0.3 勘误(2026-06-15)**：原方案用 `--agent build`，实测发现 `build` 是 Prometheus Plan Builder 的 subagent，OMO 的 Hephaestus system prompt（GPT-5.5 专用）仍会注入 explore/subagent 编排指令——`--agent build` 改不了 system prompt 注入。正确方式是 `--pure`（opencode 官方"run without external plugins"模式），彻底绕过 OMO 插件。实测 `--pure` 后 GPT-5.5 输出干净，无 explore/intent-detection 干扰。

**规则**：所有 opencode 审查调用**固定 `--pure`**（无外部插件模式，不带 OMO 编排注入）。审查要的是"模型直接读+判"，不是"编排子任务"。

```bash
opencode run --pure -m <model> --dir "${PWD}" --format json "<short prompt>"
```

这优先于模型选型——**不绕编排，选再好的模型也被带跑偏**。同步修 30-delegation.md + agent-review-protocol §8/§opencode 模板(加 --pure)。

> ⚠️ 之前 12 家横评的"模型质量分层"结论受编排污染,需 `--pure` 干净模式复核才作准。

### D1. primary 主审 — 固化，反向编码 vendor 选异构

异构是**硬约束**（红线 #8），不能靠 agent 临场选（给自由度它可能不执行）。安装时**固化**:

| 编码 vendor | primary 审查 | 理由 |
|------------|-------------|------|
| Claude (OMC) | **GPT** | 异构 + 推理强，默认场景双赢 |
| GPT (OMX/codex) | **Claude** | 此时必须 Claude，用 GPT 就同源自审 |
| 其他/OpenCode | GPT（默认） | 异构 + 推理强 |

"GPT 优先（推理强）"成立的前提是"编码非 GPT"（绝大多数=Claude Code）。编码本身是 GPT 时，**异构优先级 > GPT 推理强**。

- 编码 vendor 探测：按安装平台推断（OMC=Claude / OMX=GPT / OMO=默认模型）+ 允许用户 override
- `primary_diff`：审代码 diff 用 `codex review`（自带 sandbox+结构化）；审文档用 `opencode gpt-5.5` 短 prompt（codex exec 审文档易跑偏，本会话实证）

### D2. panel 副审 — 动态 pool（推荐列表 ∩ 实测可用）

- **混合**：agent-gates 内置推荐列表（随版本更新）∩ 安装时 `opencode models` 实测可用 → `panel_pool`
- **pool 尽量大**（抗下线——GLM/ds-flash 空就是教训，不知道哪个哪天废）
- **上线 2 家**，运行时模型**从 pool 内挑**（给自由但限定池内，不放飞）
- 排除：跟 primary 同 vendor / 跟编码同源 / flash 小模型

### D3. 触发分级（fallback vs panel）

| 场景 | 策略 |
|------|------|
| 日常小审查（单文件/短补丁） | **fallback**：只 primary，成功即停（省） |
| 关键决策（方案/安全/架构/多文件） | **panel**：primary + 2 副审（多视角） |

判定"关键"复用 Gate 2 阈值（多文件且 >50 行 / 单文件 >150 行 / 触及 §危险类别）。

**panel_mode 开关(用户提，可在 .local.json override)**:

| `panel_mode` | 行为 | 适合 |
|-------------|------|------|
| `auto`(默认) | 按重要性分级:日常只 primary,关键决策才 panel | 多数人 |
| `off` | **永远只 primary 单审** | 要快/省,信任单道异构 |
| `always` | 每次都 panel | 高要求/关键项目 |

**关键:关 panel ≠ 无异构审查**。primary 本身已是反向异构(Claude 编码→GPT 审),`off` 走的是"单道异构审查",仍满足红线 #8。panel 只是"多 1-2 道交叉视角",关掉是省交叉,不是退回同源自审。

### D4. 兜底链（有审核 > 无审核）

```
primary(固化) → 失败 → panel[0] → 失败 → panel[1] → 失败 → agent-tool(L0 同源,最后底线)
```

primary 挂了不放弃，panel 顶上降级。每一跳都用 with-timeout 包裹（macOS 无 timeout，复用 v1.10.1 的 node wrapper）+ 无效输出检测（空/损坏→下一跳）。

**⚠️ Gate 2b 死锁解决（kimi 审查，★★★）**：兜底链末端 `agent-tool` 是 L0 **同源**，但 Gate 2b(v1.7.0) 正是拦截 L1+ 机器上的同源审查——降级产出的 review 带 L0 标记会被自家 Gate 2b 拦掉,"有审核>无审核"被否决。解决:
- 全异构链(primary + 整个 panel)**都失败**、被迫降级到 agent-tool 时,在 review 文件写 `<!-- HETERO_EXHAUSTED: primary+panel all failed at <time> -->`
- Gate 2b 见 `HETERO_EXHAUSTED` 标记 → **降为 warn 放行**(不是 block)
- **不用 `SKIP_HETERO_CHECK=1` env**(gpt 审查指出:env 会泄漏到后续 hook,把 Gate 2b 长期降级)——**纯文件标记驱动**,作用域限本次 commit 的那份 review 文件,不污染全局
- 语义:"已尽力异构但环境全失效,降级同源 + 留痕",异构强制让位于"有审核>无审核",但**留痕可审计**,不是静默绕过
- 这要求 Gate 2b(已 ship)也加一个 `HETERO_EXHAUSTED` 例外分支——列入本版改动

**agent-tool 后仍失败**(qwen/kimi):记录错误 + 提示用户手动审查,不静默放过(Gate 2 仍要求 review 存在,缺则 block——这是正确的最终兜底)。

### D5. 可配置 — auto / local 分离（保护用户手改）

现状：doctor 无条件覆盖 `review-capability.json`，手改丢失。改为:

| 文件 | 谁写 | 重跑 doctor |
|------|------|------------|
| `review-capability.json` | doctor 自动探测 | **覆盖**（刷新模型探测） |
| `review-capability.local.json` | **用户手改** | **不碰**，优先级更高 |

消费时合并，local 盖 auto。三种操作:
- **重新检测/init** → `install --force` / 重跑 doctor 刷新 auto
- **手改** → 编辑 `.local.json`（换 primary / 增删 pool / override 编码 vendor），重跑不丢
- **出问题回退** → 删 `.local.json` 回自动探测

### D6. 安装时检测（把本会话手动横评自动化）

doctor 的 `check_cross_review_capability` 扩展:

```
1. opencode models → 列全部 provider/model（动态，不硬编码——bailian 这次就是新增的）
2. 按 vendor 归组，每组取最强档（排除 flash/claude）
3. 每 vendor 取 1 代表，短 prompt 实测（剔除 auth 失败/空/损坏）
4. 推断编码 vendor → 反向定 primary（D1）
5. 内置推荐列表 ∩ 实测可用 → panel_pool（D2）
6. 写 review-capability.json
```

**规则静态内置**（flash 剔/同 vendor 去重/claude 排除/GPT 优先），**模型名动态探测**（列表会变）。

## 8. 实现踩坑（2026-06-15）

### 8.1 `--agent build` 不绕 OMO（D0 根因勘误）

原方案 D0 用 `--agent build` 绕 OMO 编排，实测无效。

- `opencode agent list` 显示 `build` 是 **Prometheus Plan Builder 的 subagent**，不是独立 agent
- OMO 的 Hephaestus system prompt（GPT-5.5 专用）在 `--agent build` 下仍然注入 explore/subagent 编排指令
- `--agent` 参数选的是**编排角色**（Sisyphus/Prometheus/Hephaestus），不控制插件注入层
- `--pure` 是 opencode 官方 "run without external plugins" 模式，彻底绕过 OMO 插件
- 实测 `--pure` 后 GPT-5.5 输出干净（"OK"），无 explore/intent-detection 干扰

**定位过程**：跨两个会话、多次重试。第一次加 `--agent build` 后仍出现"并行派 explore"输出；第二次检查 `opencode agent list` 发现 build 是 subagent；最终通过 `opencode run --help` 找到 `--pure` 标志并验证。

### 8.2 bash 新增代码路径的三连声明顺序 bug

往 `bin/agent-gates-review` 插入 v1.12.0 新分支时，三个 bug 同时出现：

1. `PROMPT_CONTENT` / `PROMPT_LEN` 在新路径使用处之后才定义（原在 legacy 段）
2. `LEVEL` 全局变量在 legacy 分支内才初始化，新路径的 `append_marker` 读到空值
3. 四个 helper 函数（`parse_opencode_json` / `has_valid_conclusion` / `append_marker` / `output_result`）在 legacy 段定义，新路径调用时还未声明

**修复**：把所有共享定义提到 v1.12.0 `if` 分支点之前。

**教训**：往已有 bash 脚本加新 `if` 分支前，先检查新路径用到的所有变量和函数是否已在分支点之上声明。`bash -n` 只检查语法不检查变量定义顺序。

### 8.3 `ln -sf` symlink 循环（install.sh）

升级时 `create_symlinks()` 用 `ln -sf` 创建 skill 目录 symlink。目标已是指向目录的 symlink 时，`ln -sf` 跟随进入目录内部创建链接 → `<skill>/<skill>` → 自身无限递归。

**修复**：`ln -sfn`（`-n` 阻止跟随 symlink）。一个字符的 fix。

### 8.4 边界 case

- **空 panel CSV**：`IFS=',' read -ra arr <<< ""` 产出 `[""]`（含一个空串的数组），不是空数组。导致 `_try_review_model ""` 被调用。修复：split 前 `[[ -n "$panel" ]]` 守卫 + 循环内 `[[ -z "$m" ]] && continue`。
- **auto/always 语义退化**：只检查 `!= "off"` 把 auto 和 always 合并了，auto 的 severity 判断没实装。修复：auto 模式按 prompt 长度（≥500 字符）决定是否启用 panel。
- **marker 误标**：panel model 成功后 `append_marker` 硬编码 primary model 名。修复：`run_fallback_chain` 设置 `_REVIEW_MODEL_USED` 全局变量追踪实际成功的 model。
- **opencode `--format json` 重定向空文件**：非 TTY 下 stdout buffering 导致 `> file` 为空，pipe 到 parser 正常。审查脚本统一用 pipe 模式。
